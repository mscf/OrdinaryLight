# Primary secondary-record initialization experiments

Status: diagnostic only. Neither candidate is promoted; production code,
secondary ABI, and vxl8r defaults remain unchanged.

## Candidates

`full-primary-capture` removes the early full secondary-record clear. Miss,
one-bounce termination, and custom-scattering termination paths explicitly clear
before returning. Captured paths construct one complete SecondaryPathState,
including zero hit/normal fields, PDF, throughput, primary radiance, lobe signals,
position/roughness, geometry identity and the denoiser transmission bit. Paths
that do not capture but were selected for capture still clear before continuation.
The record is initialized before inline continuation can consume it.

This differs from the previously rejected removal of shader clears while relying
on a host transfer clear: the current native path omits that transfer, and this
candidate owns complete initialization on each relevant exit path.

`full-primary-clear-store` is simpler: it retains the original initialization
point but replaces eight field-wise zero writes with one zero-valued complete
record assignment. Capture and control flow are otherwise unchanged.

Both variants are temporary typed OrdinaryShade source modules generated by
`scripts/primary_capture_store_experiment.py`. No generated production shader is
edited. The full record layout is unchanged; neither removes required outputs.

## Native 4K results

RTX 5090 Laptop GPU; animated perspective close-up, 512×512 voxel scene,
GPU animation/layout, tight bounds, four bounces, one sample, 524288 paths,
compact hit outputs and production paired spatial filtering. Forty measured
frames after twelve warmups, alternating renderer order at identical animation
times. Headless GPU diagnostics exclude presentation.

| Candidate | Baseline primary | Candidate primary | Baseline total | Candidate total |
| --- | ---: | ---: | ---: | ---: |
| Deferred clear / complete capture | 4.875 ms | 4.710 ms | 18.984 ms | 18.826 ms |
| Whole-record zero clear | 4.751 ms | 4.767 ms | 18.764 ms | 18.843 ms |

The deferred-clear candidate saves only 0.157 ms total (0.8%) in this run.
That is weak evidence for adding branch-sensitive initialization changes across
material/transport variants. The simpler clear rewrite has no benefit. These
results do not establish hardware transaction counts or prove that source-level
redundant stores survive driver optimization.

Final raw and denoised HDR and compact hit identity/validity match exactly for
both 4K comparisons. Face averaging differs by at most 1.49e-7. A 321×181
per-frame smoke comparison of the deferred-clear candidate also passed all
11 animated frames with exact final HDR/hit output. Compact hit records do not
contain ray vectors; camera-ray parity was not separately checked. Full raw
secondary-record, optical-material, sparse-capture, and alternate-strategy
coverage would be required before production promotion; it is not claimed here.
